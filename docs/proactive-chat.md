# 主动聊天：会话静默后由 AI 先开口

> 状态：**2026-10-28 新增，默认关闭。** 机器人运行且 OneBot 已连接时，每 60 秒检查一次：
> 在用户显式选中的会话里，挑一个已经静默足够久、且没有触发频率 / 上限 / 未回复保护的对象，
> 由 AI 结合人格、最近聊天与记忆**现场生成**一条消息发出。
>
> **一句话**：定时任务是「到点发固定内容」，主动聊天是「静默够久后现场想一句话」。
>
> 入口：App → 机器人 → **主动**（`ProactiveChatPanel`）。
> 相关：[`architecture.md`](architecture.md)、[`core-services.md`](core-services.md)、
> [`ui-design.md`](ui-design.md)、[`memory.md`](memory.md)、[`voice.md`](voice.md)

## 1. 功能概述

主动聊天解决的是「聊天冷场」：对方很久没说话时，让机器人像真人一样主动开个话题或关心近况。
它**不预设具体内容**，只在条件满足时调用 AI 生成一条消息；内容质量取决于人格设定、
最近聊天记录与记忆召回结果。

### 1.1 与定时任务的区别

| 维度 | 定时任务（`ScheduledTask` / 机器人 → 定时） | 主动聊天（机器人 → 主动） |
| --- | --- | --- |
| 触发 | 固定时间点 / 固定间隔，到点必发 | 会话静默超过阈值后按 60 秒轮询判断，还受单会话每日上限与失败退避约束 |
| 内容 | 用户预先写好的固定文本 | AI 结合人格、最近聊天、记忆与话题现场生成 |
| 对象 | 任务里写死的一个会话 | 用户选中的会话名单，每次挑「最久没动静」的一个 |
| 重复 | 每个周期都会发 | 同一会话有静默周期 + 每日上限 + 未回复保护 |
| 关闭 | 删除 / 暂停任务 | 总开关默认关闭，空名单不发送 |

两者互不影响：定时任务仍由 `SchedulerService` 按计划触发，主动聊天走独立的运行循环；
2026-10-28 起两者都位于「机器人」页的子栏目，侧边栏不再单列定时任务。

## 2. 设置项

所有字段随当前微信账号的 `profile.json` 保存（`bot.proactive`）。旧配置缺该键时整块回退默认值，
不会影响其它机器人设置解码。写入与读取都经过 `ProactiveChatSettings.sanitized` 收敛，
手改配置里的越界值不会让功能进入「看起来开着但永远不生效」的状态。

| 设置 | 默认值 | 范围 / 说明 |
| --- | --- | --- |
| 启用主动聊天 | 关闭 | 总开关。关闭时不轮询、不发送，也不消耗 AI 额度 |
| 主动对象（会话名单） | 空 | 私聊、群聊均可选择（公众号不在列表中且会被自动跳过）；只有被选中的会话才会收到主动消息，**空名单 = 不发送任何消息**（不是「所有会话」） |
| 静默多久后主动（`idleMinutes`） | 180 分钟 | 15 分钟–7 天。会话最后一条消息距今超过该时长才考虑；主动发送成功后机器人自己的消息会重新计时 |
| 每个会话每天最多（`maxPerConversationPerDay`） | 2 条 | 1–5 条。**只限制单个会话自己**，不同会话之间不共享额度，也不设所有会话的合计上限 |
| 对方未回复时不再主动（`skipIfUnanswered`） | 开启 | 上一条主动消息发出后对方还没回，就跳过该会话，避免自说自话与催促感 |
| 发送时段（`activeHours`） | 09:00–23:00，每天 | **兜底时段**：优先级为「会话独立时段 > 节奏（全局工作时间）> 本页时段」；会话或全局工作时间启用时，本页时段对该会话不生效。支持跨夜、按星期。空星期自动补成每天，零长度窗口自动顺延一小时 |
| 主动权提示词（`prompt`） | 内置默认文案 | 空白时回退默认文案；这段说明会和人格、最近聊天、记忆一起交给模型，应写「怎么开口」而不是写死要发的话 |
| 可选话题（`topics`） | 空 | 最多 8 个，单条超过 40 字会截断；去空白、去重；留空时由 AI 自行决定方向 |

### 2.1 归一化规则

- 会话名单：去首尾空白、丢弃空串、按首次出现顺序去重（`normalizedConversationIDs`）。
- 话题：先按原文去重，再截断到 40 字，最多保留 8 个（`normalizedTopics`）。
- 数值：`sanitized` 把静默时长与单会话每日上限夹到各自区间。
- 时段：`activeHoursSanitized` 修正越界分钟、过滤非法星期（非 1–7）；
  启用状态下星期为空补成每天；`start == end` 时把结束时间顺延一小时
  （`WorkingHours.contains` 对零长度窗口永远返回 false）。

### 2.2 时段优先级（2026-10-28 调整）

主动发送实际使用哪个时段，由 `ProactiveChatPlanner.effectiveWindow` 按固定优先级解析：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 会话独立时段（`Conversation.workingHours`） | 在「会话」页单独设置过工作时间时，以会话时段为准；会话显式设为「不限时段」则不再回退到后两级 |
| 2 | 节奏的工作时间（`BotSettings.workingHours`） | 会话未单独设置、且全局工作时间已启用时，用全局时段 |
| 3 | 主动页发送时段（`ProactiveChatSettings.activeHours`） | 仅当前两级都未启用时兜底；关闭后表示不限时段 |

主动面板会逐个列出已选会话「实际生效的时段」，运行日志/「上次检查」的原因也会注明是哪种来源。

## 3. 运行机制

### 3.1 轮询与选择

```
机器人运行 + OneBot 已连接
 → 启动主动聊天循环（Task，60 秒一跳，tolerance 15 秒）
 → 每个 tick：读设置 → 若关闭 / 名单为空，直接返回
 → 遍历当前账号的会话，逐个调用 ProactiveChatPlanner.evaluate(...)
 → 在通过全部门槛的会话里挑 lastMessageAt 最早的一个（最久静默优先）
 → 生成并发送一条；同一 tick 最多发一条
```

- 上一 tick 还没结束（`proactiveSending`）时直接跳过，不排队、不并发。
- 只有一个会话满足条件时就是它；并列最久时保留列表中先出现的那个。
- 遍历顺序与「会话」页一致（`store.conversations`）。

### 3.2 判定门槛与顺序

`ProactiveChatPlanner.evaluate` 是纯函数（不读数据库、不发网络），按「便宜且硬的门槛 → 时间 → 频率」
的顺序判定；任一条不通过就返回 `skip(reason)`。运行循环会把本轮结论写进设置页的
「上次检查」提示（发送成功/失败另记运行日志），便于排查为什么没有发。

| 顺序 | 门槛 | 不通过时 |
| --- | --- | --- |
| 1 | 总开关已启用 | `主动聊天未启用` |
| 2 | 会话在主动名单里 | `会话不在主动聊天名单` |
| 3 | 会话 AI 回复未关闭 | `会话已关闭 AI 回复` |
| 4 | 会话类型不是公众号（群聊也可主动；已移除仅私聊限制） | `公众号不支持主动聊天` |
| 5 | 不在黑名单 | `会话在黑名单中` |
| 6 | 当前时间在生效时段内（会话独立 > 全局工作时间 > 主动页兜底） | `不在会话独立时段` / `不在节奏的工作时间` / `不在主动页时段` |
| 7 | 该会话今日未到上限（跨日先清零） | `此会话今日主动已达上限（N 条）` |
| 8 | 未开启未回复保护，或上一条已被回复 | `上一条主动消息还没有回复` |
| 9 | 有聊天记录且静默时长足够 | `会话还没有聊天记录` / `静默时间不足，还需 N 分钟` / 时间异常 |
| 10 | 上次生成/发送失败后已过固定退避（30 分钟） | `上次生成/发送失败，约 N 分钟后重试` |

静默判定用**会话的 `lastMessageAt`**（不是内存消息数组的时间）；会话列表里拿不到该字段时
回退到内存中最后一条消息的时间。成功发送后的间隔完全由静默时长决定：
`lastAttemptAt` 晚于 `lastSentAt` 才视为失败并进入 30 分钟退避，
因此不需要额外的「最小间隔」设置，也不再有每分钟重掷的概率。

### 3.3 生成与发送

- 通道与模型：会话的 `providerID` / `model` 覆盖 → 机器人默认通道 / 模型；人格自带模型时以人格为准。
  未配置可用通道或 Keychain 里没有该通道的 Key 时，记一条 warning 并放弃本次发送。
- 提示词：与普通回复共用同一套 system 段（人格正文、通用聊天规则、当前时间、会话类型与名称、
  会话备注/记忆召回），再追加：
  - `现在是主动聊天场景：对方最近没有发新消息，由你主动开口。`
  - `主动聊天的要求：<promptText>`
  - 有话题时：`可以自然聊到这些话题（不要生硬罗列）：…`
  - 只输出一条消息正文的格式约束。
  随后是最近历史（incoming → user、outgoing → assistant，群聊每条带 `昵称(wxid)：` 前缀，
  条数 `min(max(2, maxContextMessages), 10)`），最后是一条 user 操作提示
  `（这是系统的操作提示，不是对方发来的消息）请直接输出你要主动发送的消息。`
- 记忆 v2：注入人格设定与记忆卡召回时才启用；召回 query 由最近 4 条聊天 + 自定义话题 + 提示词拼成，
  避免「本轮没有对方发言」导致查询为空。
- 分段：主动聊天 **固定只发一条**：生成时关闭拟人化分段/延迟（`proactivePlanSettings`），
  避免一次主动变成连续几条自言自语；每日计数按「一条主动消息」+1。
- 失败处理：按 `ai.retryCount` 重试（间隔 400ms 递增），仍失败则记 error、写聊天面板的失败状态；
  账号切换或机器人停止会取消发送，不写入发送成功计数。

### 3.4 dry-run

- **dry-run（演练模式）**：`bot.dryRun` 开启时仍会调用 AI 生成，但只把结果写进运行日志
  （`（dry-run）将主动发送 → 会话：正文`），不投递、不计入每日条数；尝试时间照常记录，
  因此同样进入 30 分钟失败退避，避免每分钟重复调用 AI。

### 3.5 状态持久化与跨日清零

运行期状态保存在当前账号数据库的 `settings` 表，键 `proactive.state`（`ProactiveChatRuntimeState`）：

| 字段 | 含义 |
| --- | --- |
| `dayKey` | 统计所属日期（`yyyy-MM-dd`，本地时区） |
| `totalSentToday` | 今日所有会话合计已发送条数（仅展示，已不作为封顶依据） |
| `conversations[id].lastAttemptAt` | 最近一次尝试（成功或失败），失败退避用 |
| `conversations[id].lastSentAt` | 最近一次成功发送 |
| `conversations[id].sentToday` | 该会话今日已发送条数 |
| `conversations[id].awaitingReply` | 上一条主动消息发出后对方尚未回复 |

- 每天第一次 tick（以及 App 启动读取状态时）调用 `beginDay`：`dayKey` 变化时清零
  `totalSentToday` 与各会话 `sentToday`，**保留** `lastSentAt` / `lastAttemptAt` / `awaitingReply`，
  所以跨日后失败退避与「还没回」仍然有效。
- 生成前先 `noteAttempt` 并落盘：生成失败 / 发送失败后进入 30 分钟固定退避，避免每分钟重试烧 token。
- 发送成功后 `noteSent`：会话与全局计数各 +1、置 `awaitingReply = true`，再次落盘。
- 收到对方的入站消息（`!event.isSelf`）时 `noteIncoming` 清除 `awaitingReply`；
  只有状态真的变化才写库，历史回放也算，避免重启后状态失真。
- 「机器人 → 主动」页顶部展示今日已发条数与最近一次发送时间（`AppStore.proactiveSentToday` /
  `proactiveLastSentAt`）。

### 3.6 重启与账号切换

- 启动时读回 `proactive.state` 并执行一次 `beginDay`，所以重启后不会因为计数归零而立刻重发，
  也不会忘记「对方还没回」。
- 运行期状态按账号库隔离：切换微信账号后读取的是新账号自己的设置与状态；
  运行中切换会停止机器人，需要手动重新启动（见 [`accounts.md`](accounts.md)）。

## 4. 安全边界

- **默认关闭**：升级后不会突然开始自动找人聊天；必须用户显式启用并选择对象。
- **空名单不发**：名单的语义是「主动对象」而不是「白名单」；空的 `conversationIDs` 表示没有对象，
  不会退化成对全部会话生效。
- **黑名单优先**：即使会话被选进主动名单，只要命中机器人黑名单就直接跳过。
- **频控三层**：静默周期（发送成功后重新计时）、单会话每日上限、失败退避；
  不同会话之间不共享每日额度，同一 tick 最多发一条。
- **未回复保护**：默认开启；对方回话前不会对同一会话连续主动。
- **失败退避**：生成/发送失败都记一次尝试，避免「AI 报错 → 每分钟重试」。
- **时段按优先级生效**：主动聊天不会绕过会话/全局的工作时间设置；只有前两级都未启用时才用主动页的兜底时段。
- **演练模式**：可在不真正发送的情况下验证提示词与人格效果。
- **账号隔离**：设置随 `profile.json`、状态随账号数据库保存，换号后互相不可见。

## 5. 常见问题

### 5.1 为什么没有主动发消息？

按顺序自查：

1. 机器人是否运行、OneBot 是否已连接（主动聊天只在运行中执行）；
2. 「主动聊天」总开关是否开启，「主动对象」里是否选了会话；
3. 该会话是否关闭了 AI 回复、是否在黑名单；
4. 当前时间是否在该会话的生效时段内（会话独立时段 > 全局工作时间 > 主动页兜底时段）；
5. 会话最后一条消息距今是否超过「静默多久后主动」；
6. 该会话今日是否已到「每个会话每日上限」（不同会话不共享额度）；
7. 上一条主动消息发出后对方是否还没回复（未回复保护）；
8. 上次生成/发送是否失败、是否仍在 30 分钟退避期内。

设置页「上次检查」会显示最近一轮的结论（例如「没有发送：静默时间不足，还需 N 分钟」）；
运行日志里搜 `Proactive` 分类可看到发送结果（info/error）与失败原因。
另外：AI 通道未配置或 Keychain 缺 Key 时不会发送，会记 `「通道名」未配置 API Key，无法主动聊天`。

### 5.2 会不会连发 / 刷屏？

不会：同一 tick 最多处理一个会话并且最多发出一条主动消息；同一会话发送成功后要重新等一个
静默周期，并且有单会话每日上限与默认开启的未回复保护。不同会话不共享每日额度，也不设全局合计上限。
失败只会记录尝试并进入 30 分钟退避，不会在下一个 tick 立刻重试。
主动聊天固定只发一条，不受「节奏 → 拟人化」分段设置影响，避免一次主动变成连续几条。

### 5.3 换微信账号后设置和状态是否隔离？

隔离。主动聊天设置随当前账号的 `profile.json` 保存，运行期状态（今日计数、等待回复、
上次发送时间）保存在该账号自己的数据库；会话名单本身也是按账号各自的会话列表选择的。
切换账号后看到的是新账号的配置，不会把消息发到另一个账号的联系人。

### 5.4 重启 App 会不会重复发送？

正常不会。状态在发送前（尝试）与发送后（成功）都会落盘，启动时读回并执行跨日清零，
所以重启后既不会立刻重复，也不会忘记失败退避与「还没回」。
只有极端时序（消息已发出、`noteSent` 尚未落盘时进程被强制结束）才可能重复一条，
这也是状态选择「先记尝试再生成」的原因。

### 5.5 主动消息会进聊天记录和记忆吗？

会作为一条普通的机器人出站消息写入当前会话的聊天记录（与手动发送/普通回复一致），
因此会出现在会话列表、消息表和后续提示词的历史里。它也会像普通发送一样触发记忆维护：
全量互动同步会把这条文本写进记忆卡，攒够批量阈值后进入 AI 提取。
主动聊天本身不会额外触发一次提取，也不会把「主动」这件事写进记忆。

### 5.6 群聊也可以主动吗？

可以。主动对象同时支持私聊和群聊（2026-10-28 起移除了「只对私聊」限制），
但群聊主动同样受黑名单、生效时段、静默时长、单会话每日上限与未回复保护约束。
群聊里主动发言打扰面更大，建议只选择必要的群，并保持较低的每日上限。
